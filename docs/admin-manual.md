# 自治会アプリ 役員向け 運用マニュアル

下ノ沢自治会の LINE アプリ「野州シモノサワCommunity」を **役員のみなさんが日々運用するためのマニュアル** です。
専門用語はなるべく使わず、画面で「どこを押せばいいか」が分かるように書いています。

## 1. このアプリでできること

このアプリは LINE の「公式アカウント」から開く、自治会専用のミニアプリです。
住民が見られる画面は次の 5 つです。

| 下部メニュー | 内容 | 役員の主な仕事 |
| --- | --- | --- |
| 🏠 ホーム | 課題ヒーロー + 最新お知らせ | (自動で表示されます) |
| 🎯 新設課題 | 新自治会設立に向けた検討中の課題 + 投票 | **課題の追加・投票選択肢の設定** |
| 📢 お知らせ | 自治会からのお知らせ + イベント案内 (1 つの一覧にバッジ付きで表示) | **記事の投稿** (お知らせ / イベント 両方) |
| 📜 回覧板 | 紙の回覧書類を撮影して共有 | **アプリから写真をアップロード** ([8-B 章](#8-b-デジタル回覧板-紙書類を撮影してアップロード) 参照) |
| 💬 要望 | 住民からの質問・要望 + いいね | **モデレーション・回答** ([6 章](#6-投票結果やコメントを確認する) 参照) |
| 📋 生活 | ゴミ出し・防災など暮らしの情報 | **生活情報の投稿** |

下部メニューのほかに、ホーム画面の「🤖 AI相談」から **AI に質問できるページ** を開けます ([8-C 章](#8-c-ai相談-住民の質問に-ai-が答える) 参照)。役員の仕事は **AI用資料の追加と質問ログの確認** です。

## 2. 役員が使う管理ツール (microCMS)

このアプリの「中身」(記事や課題など) は **microCMS (マイクロシーエムエス)** という管理ツールで編集します。
住民は触れません。役員だけがログインできます。

### 2-1. microCMS にログインする

1. ブラウザ (Chrome / Safari など) で [https://shimonosawa.microcms.io/](https://shimonosawa.microcms.io/) を開く
2. 役員アカウントのメールアドレスとパスワードを入力
3. ログイン後、左サイドバーに以下の API (= データの種類) が並んでいます:
   - **articles** … お知らせ / イベント / 生活情報
   - **tasks** … 新設課題
   - **inquiries** … 住民からの要望投稿 (将来用)

> 🔐 アカウントの追加・削除は「管理者」権限のある役員にお願いしてください。

### 2-2. 公開と下書きの違い

microCMS では「公開」と「下書き」が選べます。

- **公開**: 住民のアプリにすぐ反映されます (最大 1 分のキャッシュあり)
- **下書き**: アプリには出ません。役員だけが microCMS で見られます

「とりあえず保存しておきたい」「複数人でレビューしたい」時は下書きで保存し、合意できたら公開に変更してください。

## 3. お知らせ・イベント・生活情報を投稿する

3 つとも同じ `articles` という箱に入れます。区別は「カテゴリ」で行います。

### 3-1. 手順

1. microCMS の左サイドバーで **articles** を開く
2. 右上の **「+ 追加」** ボタンを押す
3. 以下を入力:

| 項目 | 必須 | 書き方 |
| --- | --- | --- |
| title | ✅ | 一覧に出る見出し。50 文字以内推奨 |
| body | ✅ | 本文 (リッチエディタ。見出し / 太字 / 画像 OK)。一覧カードには冒頭が自動で抜粋表示されます |
| category | ✅ | `news` / `events` / `life` から 1 つ選ぶ |
| subCategory | (任意) | お知らせ画面のサブカテゴリ: `association` (自治会運営) / `land_development` (土地開発)。未設定は「自治会運営」扱い |
| image | (任意) | カードに大きく表示されるトップ画像 |
| important | (任意) | チェックすると 🔴 重要バッジが付く |
| pdfUrl / pdfFileName / pdfFileSize | (任意) | [7 章](#7-pdf-を添付したい時) 参照 |
| rsvpEnabled | (任意) | [4 章](#4-清掃活動など参加表明-rsvp-付きのイベントを投稿する) 参照 |

4. 右上の **「公開」** を押す
5. 住民のアプリに反映されるまで **最大 1 分** ほどかかります

### 3-2. カテゴリの使い分け

- **news (お知らせ)**: 総会のご案内、決定事項の周知、緊急連絡など
- **events (イベント)**: お祭り、清掃活動、防災訓練、定例会など日付のある催し
- **life (生活情報)**: ゴミ出しカレンダー、防災マップ、各種申請窓口など、年中使う情報

> 💡 住民の画面では **`news` と `events` は同じ「📢 お知らせ」ページに一緒に表示** されます (カテゴリバッジで区別)。役員が microCMS で入稿する時はカテゴリを正しく選び分けてください。
> `life` は別画面 (📋 生活) です。

### 3-2-A. サブカテゴリ (subCategory) の使い分け

お知らせ画面 (📢) には **「すべて / 🏘 自治会運営 / 🌱 土地開発」** の 3 つのタブがあり、住民は関心のあるトピックだけを絞り込めます。この振り分けは microCMS の `subCategory` フィールドで指定します。

| 値 | 表示 | 想定内容 |
| --- | --- | --- |
| `association` | 🏘 自治会運営 | 会費・総会・役員会・清掃活動など、日常的な自治会の運営に関わる話題 |
| `land_development` | 🌱 土地開発 | 新自治会設立エリアの土地開発・造成・分譲・整備など、開発事業に関する話題 |

> ⚠️ **microCMS 側で `subCategory` フィールドを追加する必要があります**。
> - フィールド ID: `subCategory`
> - 種類: セレクトフィールド (単一選択)
> - 選択肢: `association`, `land_development`
> - 未設定でも投稿は可能。フィールド追加以前の既存記事は自動的に「自治会運営」タブに振り分けられます。

### 3-3. 「重要」マークの使いどころ

`important` にチェックを入れると、一覧で赤い「重要」バッジが付きます。
**月に 1〜2 件まで** に絞ると効果的です。乱発すると埋もれます。

### 3-4. お知らせへのコメント (住民同士のやりとり)

お知らせ (`news`) やイベント (`events`) の詳細ページには **住民がコメントを投稿できる欄** があります。

- 住民は LIFF ログイン済みなら **匿名 (「自治会員」表示)** でコメント可能
- 投稿本人だけが自分のコメントを削除できる (ソフトデリート)
- 記事タイトル下・本文の下に「💬 コメント」セクションで一覧表示 (新しい順)
- 内部的には Supabase の `article_comments` テーブルに保存

不適切コメントが投稿された場合の対応は課題コメント (6-3 章) と同じで、投稿者本人が削除するか、開発担当に Supabase 側からの削除を依頼してください。

> ⚠️ **Supabase 側に `article_comments` テーブルの作成が必要** です。マイグレーション SQL は本機能を導入した PR (#51) 本文に記載しています。

## 4. 清掃活動など、参加表明 (RSVP) 付きのイベントを投稿する

イベント記事に「参加 / 不参加 (別日実施予定) / 別日実施済み」を住民が回答できる機能です。

### 4-1. 有効化の手順

1. 通常通り [3 章](#3-お知らせイベント生活情報を投稿する) と同じ手順で `articles` を 1 件追加
2. category は **`events`** を選ぶ
3. **`rsvpEnabled`** にチェックを入れる ✅
4. 公開

これだけで、住民の詳細画面に「参加 / 不参加 / 別日実施済み」のボタンが出ます。

### 4-2. 回答状況を確認する

回答は **Supabase という別のデータベース** に溜まります。役員が見るには:

- アプリ側に「回答一覧画面」はまだ実装していません
- 暫定: Supabase 管理画面 ([https://supabase.com/dashboard](https://supabase.com/dashboard)) にログインし、`cleanup_rsvps` テーブルを `article_id` で絞り込んで確認

> 💡 「アプリ内で回答一覧を見たい」というご要望が出てきたら、開発担当に連絡してください。専用画面を追加できます。

## 5. 新自治会設立の「課題」を投稿する (投票機能つき)

役員が叩き台を作り、住民に投票・意見を募るための機能です。

### 5-1. 手順

**おすすめ: アプリ上で作成 (微CMS に行かなくて OK)**

1. アプリの 🎯 新設課題 タブを開く
2. 上部に **「🛡️ 役員: 課題を作成 / 編集」** リンクが表示される (役員のみ)
3. タップ → `/admin/tasks` の管理ページが開く
4. 右上の **「＋ 新規作成」** を押す
5. タイトル / 本文 (リッチエディタで画像も貼れる) / ステータス / 優先度 / 表示順 / 投票設定 を入力
6. **「作成する」** を押す → 一覧に即時反映
7. 既存課題の編集は管理ページの「編集」または、課題詳細ページ上部の「🛡️ 役員: 編集」リンクから可能
8. 削除も編集画面下部の「🗑 削除」ボタンから可能

> 💡 アプリで作成した課題も従来通り **microCMS の tasks にも保存** されるので、microCMS 側から見ても同じデータが入っています。

#### microCMS 側で操作したい場合 (従来通り)

1. microCMS の **tasks** を開く → **「+ 追加」**
2. 以下を入力:

| 項目 | 必須 | 書き方 |
| --- | --- | --- |
| title | ✅ | 課題名 (例: 「集会所の場所をどうするか」) |
| body | ✅ | 詳しい背景・選択肢の解説 (リッチエディタ、画像可)。一覧カードには冒頭が自動で抜粋表示されます |
| status | ✅ | `open` / `in_progress` / `resolved` から選ぶ |
| priority | (任意) | `high` / `medium` / `low` |
| displayOrder | (任意) | 数字。**小さいほど上に表示** されます (1, 2, 3...) |
| voteMode | (任意) | 回答方式: `single` (単一選択・既定) / `multiple` (複数選択可) / `freetext` (自由入力)。詳細は [5-3](#5-3-投票選択肢の書き方) |
| voteOptionsRaw | (任意) | 投票選択肢を **改行区切り** で入力 (`single` / `multiple` のみ。`freetext` では無視される) |
| voteDeadline | (任意) | 回答期限 (日付) |

3. **「公開」** を押す

### 5-2. ステータスの意味

| 値 | 意味 | 使うタイミング |
| --- | --- | --- |
| `open` | 未着手 | 課題は立てたが、まだ議論前 |
| `in_progress` | 検討中 | 投票中・意見募集中 |
| `resolved` | 方針確定 | 役員会で結論が出た。投票はもう受け付けない |

> 💡 🎯 新設課題タブの一覧は、開いた直後は **「確定済み以外」(`open` / `in_progress`)** に絞り込まれた状態で表示されます。`resolved` にした課題は一覧上部の **「確定済み」** または **「すべて」** ボタンを押すと表示されます。

### 5-3. 投票選択肢の書き方

`voteOptionsRaw` フィールドに、選択肢を **改行で 1 行ずつ** 書きます。選択肢の数は何個でも OK。

例:
```
賛成
反対
どちらでもない
```

#### 回答方式 (voteMode)

`voteMode` セレクトで、住民の回答方式を 3 つから選べます。

| 値 | 表示 | 動作 |
| --- | --- | --- |
| `single` (既定) | 🗳 投票または回答 (単一選択) | ラジオボタンで 1 つだけ選ぶ。**「反対」を含む選択肢を選んだ住民は理由の入力が必須** |
| `multiple` | 🗳 投票または回答 (複数選択可) | チェックボックスで何個でも選択可。理由欄は無し |
| `freetext` | 📝 自由回答 | 選択肢を使わずテキストエリアに自由記述。**個人回答で、他の住民からは見えません** (役員のみ Supabase で参照可) |

> 💡 `freetext` モードでは `voteOptionsRaw` は使われません。本文 (body) で「どのテーマについて聞きたいか」を案内するだけで OK です。

> ⚠️ `single` モードの「反対理由必須」は、ただ反対するのではなく、改善のための声を集めるための仕組みです。

### 5-4. 回答期限

`voteDeadline` に日付を入れると、その日を過ぎたら回答が受け付けられなくなります (`single` / `multiple` は集計表示は継続、`freetext` は受付終了の表示のみ)。
未設定なら無期限です。

### 5-4-A. 世帯ごと 1 票で集計する仕組み

投票は **1 世帯あたり 1 票** で集計されます。

#### 仕組み
- 投票画面の上部に「世帯名 (必須)」入力欄があり、住民は自分の世帯名を入力
  (例: 「山田家」「鈴木」など)
- 同じ世帯名で **誰が再投票しても前回の回答が上書き** される (家族の誰かが投票済みでも、別のメンバーが同じ世帯名で投票すれば 1 票として更新)
- 世帯名はその端末の localStorage に保存され、次回からは自動でプリフィルされる
- 集計時もユニーク世帯数として表示される

#### 注意点 / 限度
- 自己申告制 (Honor System): 別の世帯名を入力すれば複数票投じることは技術的に可能。役員側で投票一覧を見て不審な世帯名がないか確認できる
- スペース・表記揺れ (「山田家」「山田」「ヤマダ」など) は **別世帯としてカウント** されます。住民への案内では「ご家庭で表記を統一してください」と伝えるとよい
- 世帯名導入前の旧投票 (世帯名なし) は LINE アカウント単位 (line_user_id) で 1 票としてカウント (後方互換)。住民が再投票することで自動的に世帯ベースに置き換わります

> 💡 役員専用「回答一覧」ページ (`/tasks/[id]/responses`) でも、世帯名がある投票は **世帯名で表示** されます (旧投票は会員名で表示)。

### 5-5. 住民による回答の修正・取り消し

- 住民は **何度でも回答を変更** できます (期限内なら)。再送信のたびに最新の回答に上書きされます
- 回答済みの住民には **「回答を取り消す」リンク** が表示され、これを押すと自分の回答がデータベースから削除され「未回答」状態に戻ります
- 期限切れ後は変更も取り消しもできません

### 5-6. 優先度と表示順

- `priority` は「重要度」のラベル表示用 (一覧で 🔴/🟡/⚪ のバッジ)
- `displayOrder` は「どの順番で並べたいか」を数値で指定

両方未設定の場合は **公開日が新しい順** に並びます。

### 5-7. 投票後役員まとめの入力・表示

各課題には **「🏛️ 投票後役員まとめ」専用ページ** (`/tasks/[id]/resolution`) があります。役員会などで結論が出た後、役員がまとめて入力する場所です。

> ⚠️ **カードは方針確定 (`resolved`) の課題にのみ表示されます。** ステータスが `open` (未着手) や `in_progress` (検討中) の課題では、住民・役員のいずれにもカードが出ません。まとめを入力したい場合は先に「5-2. ステータス」を `resolved` に更新してから、詳細ページを開き直してください。

#### アクセス
1. 先に対象課題のステータスを `resolved` (方針確定) に変更する ([5-2](#5-2-ステータスの意味))
2. 対象の課題詳細ページを開く
3. 本文の下に表示される「🏛️ 投票後役員まとめ」カードをタップ (未決なら未決バッジが付きます)
4. 投票後役員まとめページに遷移

#### 役員が入力する項目
役員でアクセスすると、上部に紫色の編集フォームが表示されます:

| 項目 | 内容 |
| --- | --- |
| 議決結果 | 可決 / 否決 / 保留 / 未決 の 4 択 (未決 = デフォルト) |
| 議決日 (任意) | 会議で結論が出た日付 |
| まとめ | リッチエディタ (画像・見出し・リンクなど可)。決定内容、経緯、条件などを記載 |

「議決結果を保存」で反映、「🗑 内容をクリア」で未決状態に戻します。

#### 住民に見える表示
- **入力あり**: バッジ (可決/否決/保留) + 議決日 + まとめ本文が表示される
- **未決/未入力**: 「この課題はまだ議決されていません。役員会で結論が出た後、こちらにまとめが掲載されます」表示

> ⚠️ **microCMS 側に以下 3 フィールドの追加が必要** です。追加していないと保存時に 500 エラーになります。
> - `resolutionOutcome`: セレクトフィールド (単一)。選択肢: `approved`, `rejected`, `deferred`, `undecided`
> - `resolutionSummary`: リッチエディタ (HTML)
> - `resolutionDate`: 日付

## 6. 投票結果やコメントを確認する

### 6-1. 投票結果

住民は **アプリの課題詳細ページ** で投票結果 (棒グラフ + 反対理由) を見られます (`single` / `multiple` モード)。

`freetext` (自由回答) モードは個人回答のため住民側には件数だけ表示され、本文は見えません。本文を確認するには Supabase の `votes` テーブルを `task_id` で絞り込んでください (`selected_option` 列に回答本文が入ります)。
役員も同じ画面で確認できます。LIFF ログインさえできていれば誰でも結果は閲覧可能です (匿名集計)。

### 6-2. 役員向け: 名前付きの回答一覧を見る (アプリ内)

役員 (`members.is_admin = true` のアカウント) は、課題詳細ページの投票パネル右下に **「🛡️ 役員: 回答一覧を見る」** リンクが出ます (一般住民には表示されません)。

押すと `/tasks/[id]/responses` の **役員専用ページ** が開き、以下を会員名付きで確認できます:

- 単一選択: 各会員が選んだ選択肢 + 理由 (反対の場合)
- 複数選択: 各会員がチェックしたすべての選択肢
- 自由入力: 各会員の本文 (個人回答が住民同士に見えないモード)

アカウントが `members` に未登録の住民は **「(未登録)」** と表示されます (まだアプリにログインしていない / 自動登録が失敗したケース)。

> 💡 役員アカウントの設定方法は [11 章](#11-役員アカウントの設定方法) を参照してください。

### 6-3. コメント機能

各課題には住民がコメントできます。各コメントに **👍 (いいね) ボタン** が付いており、賛同や共感を数値で見える化できます。

**不適切なコメントが投稿された時**:

- そのコメントは本人 (LINE userId が一致する人) のみ「削除」ボタンが押せます
- 役員が他人のコメントを削除する仕組みは今はありません
- どうしても削除が必要な時は開発担当に依頼して Supabase 側で直接削除してもらいます

**👍 いいねの仕組み**:

- LIFF ログイン済みの住民のみ押せる (1 人 1 回)
- もう一度押すと取り消し (行削除)
- Supabase の `comment_likes` テーブル (`comment_id, line_user_id` の PK) で管理
- 集計は SSR で計算し、コメント一覧に埋め込む

## 7. PDF を添付したい時

総会資料・規約・チラシなどの PDF は、記事に添付できます。

### 7-1. 仕組み

PDF 本体は **Cloudflare R2** という保存場所にアップロードします。
microCMS には「PDF の URL」だけを書きます。

### 7-2. 手順

1. 開発担当または管理者役員から **R2 のアップロード方法** を共有してもらう
   (もしくは自治会公式の Dropbox / Google Drive を使う運用に切り替える)
2. アップロード後の **直接 URL** をコピー
3. microCMS の articles に該当記事を作成 / 編集
4. 以下 3 フィールドを埋める:
   - `pdfUrl` … コピーした URL
   - `pdfFileName` … 住民の画面に表示する名前 (例: `2026年度総会資料.pdf`)
   - `pdfFileSize` … ファイルサイズ (バイト数。任意。書くと「2.3 MB」と表示されます)
5. 公開

> 💡 PDF を差し替えた時は、URL も変わるので microCMS の `pdfUrl` も更新してください。

## 8-A. 住民の要望投稿 (リッチエディタ + 画像)

住民が「💬 要望」から質問・要望を投稿する画面は **リッチエディタ** になっており、太字・見出し・リスト・リンク・画像が使えます。

### 8-A-0. 投稿の公開 / 非公開を切り替える (役員専用)

住民から投稿された要望/質問は **初期状態は「🔒 非公開」** になっており、住民の一覧には出ません。
役員が内容を確認して問題なければアプリ上で **「🌐 公開」に切り替える** ことで初めて一覧に出ます。

#### 操作手順
1. 役員 (`is_admin = true`) が `/inquiries` を開く
2. 上部に **「🛡️ 役員: 公開設定」** リンクが表示される (一般住民には非表示)
3. タップすると `/admin/inquiries` に遷移し、以下のタブが出る:
   - 🔒 **未公開** (デフォルト) … 住民からの新規投稿で、まだ公開していないもの
   - 🌐 **公開中** … 既に公開済みのもの
   - **すべて**
4. 各カードの右下にある **トグルボタン** を押すと公開/非公開を切り替え:
   - 「🔒 非公開 (タップで公開)」を押す → 即時公開
   - 「🌐 公開中 (タップで非公開)」を押す → 一覧から取り下げ

> 💡 個別の詳細ページ (`/inquiries/[id]`) を開いても、役員には同じトグルボタンが上部に表示されます。詳細を見ながら判断したい時はこちらが便利です。

> ⚠️ **microCMS 側に `isPublished` フィールド (boolean) を追加** しておく必要があります (詳細は [8-A-2 ②](#8-a-2-セットアップ-初回のみ))。

### 8-A-0-C. 回答とステータスを LIFF 上で更新する (役員専用)

質問/要望への回答や、対応状況のステータス変更は **LIFF アプリ上の詳細ページで完結** します (microCMS にアクセス不要)。

#### アクセス
1. アプリで `/inquiries` の対象の投稿をタップ
2. 詳細ページ中央付近に **「🛡️ 役員専用: 回答とステータスを更新」** という紫色のパネルが表示されます (役員にのみ表示)

#### ステータス変更
| 値 | 表示 | 使うタイミング |
| --- | --- | --- |
| `pending` | 受付中 | 新規受付直後 (デフォルト) |
| `in_progress` | 対応中 | 役員会で議論中 / 情報集めている最中 |
| `answered` | 回答済み | 公式回答を入力した後 |

ドロップダウンで選択 → **「ステータスを保存」** を押すと即時反映。

#### 回答の入力
- **回答者名** (例: 「自治会」「環境部」など) と **回答本文** を入力 → 「回答を保存」
- 既存の回答を編集する時もこの画面から上書き
- 不要になった回答は「🗑 回答を取り消す」で 3 フィールドを全て空にできる
- 保存すると住民の画面に「🏛️ 自治会からの回答」セクションとして表示される

> 💡 **回答とステータスは独立しています**。例えば「ステータスは対応中のままにして、追加情報の回答だけ載せる」「ステータスだけ回答済みにする」「両方同時に更新する」など自由に組み合わせ可能です。

### 8-A-0-B. 住民の「自分の投稿」と編集・取消 (役員操作ではない)

参考までに、住民側にも以下の機能があります (役員の操作対象ではないが、運用相談で住民に案内する時の参考):

- **「📝 自分の投稿を見る」** リンク (`/inquiries` 上部、LIFF ログイン済み住民のみ): 自分が投稿した質問・要望を一覧確認
  - バッジ: `🔒 確認中` (未公開) / `🌐 公開中` / 受付中・対応中・回答済み
- **編集**: 未公開 (🔒) の自分の投稿に限り、詳細ページの「✏️ 編集する」リンクから内容を直せる
- **取り消し (削除)**: 公開済みでも未公開でも、自分の投稿は「この投稿を削除」で取り消せる

> 💡 役員が公開する前に住民が編集して新しい本文に差し替えると、それがそのまま公開対象になります。

### 8-A-0-D. 投稿者本人への自動 LINE 通知 (公開時 / 回答時)

役員が **公開トグルを ON にした瞬間** や **回答を保存した瞬間** に、投稿者本人 (LIFF ログイン済みで投稿した人) の LINE に Push 通知が自動で届きます。

#### 通知タイミング
| イベント | 通知内容の例 | 備考 |
| --- | --- | --- |
| 未公開 → 公開 (false → true) | 「📣 ご投稿が公開されました」+ タイトル + 詳細リンク | true → false や true → true ではスキップ |
| 回答の保存 / 編集 | 「💬 ご投稿に役員から回答が届きました」+ タイトル + 詳細リンク | 編集での再保存でも毎回通知される |

#### 必要な設定
すでに [8-A-0-A](#8-a-0-a-投稿時に役員-line-グループへ自動通知する-任意) で設定済みの `LINE_MESSAGING_CHANNEL_ACCESS_TOKEN` をそのまま使います。**追加の環境変数は不要**。

注: 公式アカウントを **友だち追加していない / ブロックしている** 住民には届きません。LIFF 経由で 1 度でもアプリを開いていれば自動的に友だち追加されている前提です。

#### 通知が届かない場合の調査
- Vercel のサーバーログに `[admin/inquiries/publication] author notify failed` や `[admin/inquiries/response] author notify failed` が出ているか確認
- 投稿者の `inquiries.lineUserId` が空でないか (LIFF ログインなしで投稿された場合は空)
- 投稿者が公式アカウントをブロックしていないか (本人に確認)

### 8-A-0-A. 投稿時に役員 LINE グループへ自動通知する (任意)

住民が要望/質問を投稿した瞬間に、**役員 LINE グループに自動でプッシュ通知** することができます。
通知文には種別・カテゴリ・タイトルと、`/admin/inquiries` (公開設定ページ) への LIFF リンクが入ります。

#### 仕組み
- 公式アカウントの **Messaging API** (Push API) 経由で、指定したグループ ID に対してテキストメッセージを送る
- LINE Login (LIFF) チャネルとは別の **Messaging API チャネル** が必要
- Vercel に環境変数を 2 つ設定するだけで有効化される (未設定なら通知はスキップされ、投稿動作には影響なし)

#### セットアップ手順

##### ① Messaging API チャネルを用意
1. [LINE Developers Console](https://developers.line.biz/console/) にログイン
2. 自治会のプロバイダー → **「Messaging API」** チャネル を確認 (無ければ作成)
   - 既存の公式アカウントを Messaging API 連携した時点でチャネルが作られているはず
3. チャネル設定の **「Messaging API」** タブを開き、**チャネルアクセストークン (長期)** を発行

##### ② 公式アカウントをグループに参加させる
1. LINE の通知先にしたいグループを開く
2. メンバー追加で **公式アカウント** を招待
3. グループ設定で「グループ・複数人トークへの参加を許可」を有効化していること
   (LINE Official Account Manager → 設定 → 応答設定 → グループ・複数人トーク 「許可する」)

##### ③ グループ ID を取得する
Messaging API には「グループ一覧を取る API」が無いため、グループに公式アカウントを招待した直後の **Webhook イベント** から取得するのが一般的です。

簡単な方法:
1. LINE Developers Console → Messaging API → Webhook 設定 を一時的に有効化
2. テキトーな URL (例えば https://webhook.site/ で取得) を Webhook URL に設定
3. 招待したグループで何か発言 → webhook.site に届いた JSON の `source.groupId` ( `C` で始まる文字列) をコピー
4. webhook 設定を元に戻す (アプリ側で受け取らないので不要なら無効化に)

> 💡 もしくは開発担当に「グループ ID を取りたい」と頼めば、別途簡易スクリプトで取れます。

##### ④ Vercel に環境変数を追加
Vercel ダッシュボード → Settings → Environment Variables に以下 2 つを追加:

| キー | 値 |
| --- | --- |
| `LINE_MESSAGING_CHANNEL_ACCESS_TOKEN` | ① で発行したチャネルアクセストークン (長期) |
| `LINE_MODERATION_GROUP_ID` | ③ で取得したグループ ID (`C` で始まる文字列) |

設定後、再デプロイ (= Vercel が自動で行う) すれば次の投稿から通知が届きます。

##### ⑤ 動作確認
1. テスト用アカウントで `/inquiries/new` から要望を投稿
2. 役員グループに「📨 新規要望が投稿されました...」のメッセージが届くか確認
3. メッセージ内の LIFF リンクをタップ → `/admin/inquiries` (公開設定ページ) が開く

> 💡 通知に失敗した場合 (LINE API 5xx、ネットワーク断、トークン失効など) も、要望投稿自体は成功扱いになります。失敗内容は Vercel のサーバーログに残ります。

### 8-A-1. 画像はどこに保存されるか

住民が貼り付けた画像は **Supabase Storage** の `inquiry-images` バケットに保存され、CDN 経由で配信されます。
1 枚あたり **5MB まで** / 形式は **jpeg / png / webp / gif** に制限しています。

### 8-A-2. セットアップ (初回のみ)

#### ① Supabase Storage (`inquiry-images` バケット + ポリシー)
> 💡 テーブル・ポリシー・Storage バケットの作成 SQL は、マニュアルではなく **[docs/supabase-schema.sql](./supabase-schema.sql)** (本番の現状をそのまま書き出したもの) にまとめています。
> 本番では作成済みなので、通常この作業は不要です。環境を作り直す時だけ、SQL Editor でこのファイルを上から実行してください。

確認方法: Storage → `inquiry-images` → Policies タブに INSERT と SELECT の anon ポリシーが 2 つ並んでいれば OK です。
試しにアプリの「💬 要望」→ 新規投稿で画像挿入ボタンを押し、画像が貼り付くか確認してください。

#### ② microCMS の inquiries に `isPublished` フィールドを追加
役員が LIFF 上で公開/非公開を切り替えできるようにするためのフラグです。

1. microCMS → API スキーマ管理 → **inquiries**
2. **「フィールドを追加」** を押す
3. 以下を設定:
   - フィールド ID: `isPublished`
   - 表示名: 「公開する」など
   - 種類: **真偽値 (boolean)**
   - 初期値: **false**
4. 保存

> 💡 既存の投稿 (`isPublished` フィールド追加前のもの) は値が空のままになりますが、アプリ側では「未定義 = 公開済み」として扱うため、住民にも引き続き表示されます。新規投稿のみ初期値 `false` (= 未公開) で記録されます。

### 8-A-3. 不適切な画像が投稿された時

- 投稿者本人が「この投稿を削除」を押せば、その投稿ごと一覧から消えます
- 画像ファイル自体は Supabase Storage に残ったままになります。気になる場合は Supabase Storage の `inquiry-images` から該当ファイルを手動で削除してください
- (将来的に「投稿削除 → 画像も削除」する仕組みを検討中)

## 8-B. デジタル回覧板 (紙書類を撮影してアップロード)

市役所などから自治会に届く **紙の回覧書類** を、役員がスマホで撮影してアプリにアップロードする機能です。
アップロードされた書類は全会員が一覧から **いつでも過去分も含めて閲覧** できます。

### 8-B-1. アップロード手順 (役員)

1. アプリの下部メニュー **📜 回覧板** をタップ
2. 画面右下の **「＋ 回覧板を追加」** ボタンを押す (役員アカウントにのみ表示)
3. **タイトル** を入力 (例: 「市役所からのお知らせ (2026年5月)」)
4. **「📷 写真を撮影」** または **「🖼 アルバムから選択」** ボタンから写真を追加
   - **写真を撮影**: その場でカメラを起動して 1 枚撮影
   - **アルバムから選択**: スマホに保存済みの写真を **まとめて複数枚** 選べる
   - 1 件あたり最大 **10 枚** までまとめてアップロード可能
   - JPEG / PNG / WEBP / GIF 対応
   - **大きい写真は自動で縮小されます** (長辺 2000px / JPEG 85% 品質)。スマホで撮った原寸写真 (5〜10MB) でもそのままアップロード OK
5. アップロード完了 (各サムネに ✓ マーク) を確認したら **「公開する」** を押す
6. 一覧に即時反映されます
7. 公開から 1 分ほどで、AI が写真の文字を自動で読み取り、**AI相談で回覧板の内容に答えられるようになります** (役員の作業は不要。確認方法は [8-C-5](#8-c-5-回覧板の文字起こしを確認やり直す-役員専用))

> 💡 AI がきれいに読み取れるよう、**書類全体が画面に収まり、ピントが合った明るい写真** で撮ってください。斜めや影が濃い写真は読み間違いの原因になります。

### 8-B-2. 閲覧 / 削除

- 全会員は `/circulation` から一覧 (サムネイル + タイトル + 日付) を閲覧可能
- **新しいものが上に並びます**
- **新着の目印 (緑の枠 + 右上の点滅する ● + 太字タイトル)**: 以下の **両方** を満たす回覧板にのみ自動で付きます (住民ごとに判定):
  1. 投稿から **14 日以内**
  2. **その住民がまだ詳細ページを開いていない** (= 未読)
  → 詳細ページを 1 度でも開けば次回以降は消えます。未読のまま 14 日が経過しても自動で消えます。
  → 判定には既存の `circulation_views` テーブルを再利用しています (LIFF ログイン済みの住民のみ既読判定が有効。未ログインは常に未読扱いで、投稿から 14 日以内は全部新着表示)。
- **月で絞り込み** ができます (投稿のあった月だけが選択肢に出ます)
- 各カードをタップすると **写真がフル表示** され、さらにタップで原寸を新規タブで開けます
- 詳細画面の右下に **「🗑 この回覧板を削除」** が役員にのみ表示されます (誤投稿の取り消しに使用)

### 8-B-2-B. 「♥ 興味ある」ボタン

住民は各回覧板について **♥ 興味ある** ボタンで関心を示せます。運営のニーズ把握に使うための軽量な機能です。

- **場所**: 一覧カード右下 (♥ と件数のみ) と、詳細ページ上部
- **動作**: タップで ON/OFF (1 人 1 回。再タップで取り消し)
- **カウント**: ボタン横に総数が表示され、誰でも見られます (**誰が押したかはアプリ画面には出しません**)
- **要ログイン**: LIFF 経由でアプリを開いていないと押せません (押しても `LINE 経由でアプリを開いてください` と出る)
- ボタンを押すとピンク色に変わります
- 一覧カードの ♥ ボタンは **カードの Link を踏まずに単独で動作** するように作られているので、詳細ページを開かずに意思表示だけできます

#### 役員側: 誰が押したかを確認したい時
アプリ画面には出していないので、Supabase の SQL Editor で直接見てください。

```sql
-- 回覧板ID (circulation_id) ごとに、誰がいつ ♥ 興味ある を押したか
select ci.created_at, m.display_name, ci.line_user_id
from public.circulation_interests ci
left join public.members m on m.line_user_id = ci.line_user_id
where ci.circulation_id = '対象の circulation_id'
order by ci.created_at;
```

`display_name` が null の行は「members に未登録 (LIFF ログイン前) の住民」です。

### 8-B-2-A. 閲覧履歴の確認 (役員専用)

住民が回覧板の詳細ページを開くと **`circulation_views` テーブルに 1 行記録** されます (LIFF ログイン済みの住民のみ)。

役員は以下の手順で閲覧状況を確認できます:

1. 該当の回覧板の詳細ページを開く
2. 左下に **「🛡️ 役員: 閲覧履歴を見る」** リンクが出る (役員のみ表示)
3. タップすると `/circulation/[id]/views` の **役員専用ページ** が開く

確認できる情報:
- **ユニーク閲覧者** … 何人が見たか (重複なし)
- **延べ閲覧 (PV)** … 同じ人が複数回見た分も含めた累計
- **閲覧者一覧** … 会員名 + その人の PV + 初回 / 最新閲覧日時

> 💡 LIFF ログインしていない住民の閲覧は記録されません。会員登録 (自動) がまだの住民は「(未登録)」と表示されます。

### 8-B-3. セットアップ (初回のみ)

回覧板で使う Supabase の Storage バケット `circulation-images` と、テーブル
`circulations` / `circulation_views` / `circulation_interests` が必要です。

> 💡 テーブル・ポリシー・Storage バケットの作成 SQL は、マニュアルではなく **[docs/supabase-schema.sql](./supabase-schema.sql)** (本番の現状をそのまま書き出したもの) にまとめています。
> 本番では作成済みなので、通常この作業は不要です。環境を作り直す時だけ、SQL Editor でこのファイルを上から実行してください。

### 8-B-4. 不要になった回覧板を消したい時

- 詳細ページから役員が「🗑 この回覧板を削除」で消すと、`circulations` テーブルから当該行が消えます
- AI 用の文字起こし (`circulation_texts`) も一緒に自動で消え、AI相談でも答えなくなります (最大 5 分で反映)
- **Supabase Storage 上の画像本体はそのまま残ります** (ストレージ容量が気になる場合のみ Storage の `circulation-images` から手動削除)

## 8-C. AI相談 (住民の質問に AI が答える)

住民がホーム画面の「🤖 AI相談」から質問すると、AI (Claude) が **自治会の資料** と **アプリのお知らせ・新設課題・回覧板** をもとに回答します。
質問と回答はすべて記録され、役員は「質問ログ」画面で **どんな質問が多いか** を確認できます。

- 資料に答えがない質問には、AI は「役員にお問い合わせください」と答え、住民の画面に **「✉️ 役員に相談する」** ボタン (要望フォームへのリンク) が出ます
- 1 人 1 日 20 回まで質問できます (費用の上限のため)。アプリ全体でも 1 日 300 回で受付を止めます
- LINE からアプリを開いた住民 (会員) だけが使えます
- 費用を抑えるため、**まず安い AI (Haiku) が答え、AI 自身が「自信がない」と判断した質問だけ上位の AI (Opus など) が答え直します** (自動切り替え)。住民の画面では区別されません
- 安い AI が答えた回答の下には **「🔍 詳しい AI で答え直す」** ボタンが出ます。住民が押すと、上位の AI が同じ質問に答え直します (1 回の質問として数えます)

### 8-C-1. AI が参考にする資料

AI は次の 3 種類を読んで答えます。

| 資料 | 中身 | 役員の作業 |
| --- | --- | --- |
| アプリの記事 | お知らせ・イベント・生活情報 (新しい順に 40 件) と新設課題 | **不要** (記事を公開すれば最大 5 分で自動的に反映) |
| デジタル回覧板 | 回覧板の写真を AI が文字に起こしたもの (新しい順に 15 件・1 年以内・1 件 2,500 字まで) | **不要** (投稿すると自動で文字起こし。確認・やり直しは 8-C-5) |
| AI用資料 | 規約・総会資料・FAQ など、アプリに載っていない資料 | **追加・更新が必要** (8-C-2 参照) |

> ⚠️ **AI用資料には「住民に見せてよい資料」だけを入れてください。** AI は資料の内容をそのまま住民に答えます。
> アンケートの個別回答、LINE グループのやりとり、名簿、領収書、個人名が出る資料は **入れてはいけません**。

> 💡 一番効果があるのは **役員が書く「よくある質問 (FAQ)」** です。「会費はいくら？」「総会はいつ？」のような質問と答えを箇条書きにした資料を 1 つ作っておくと、回答の正確さが大きく上がります。

### 8-C-2. AI用資料を追加・更新する

現在は開発担当 (アプリを作っている役員) がパソコンで登録します。役員は資料を用意して渡すだけで OK です。

1. Google Drive の **「AI用資料」フォルダ** に、住民に見せてよい資料を入れる
2. 開発担当に「AI用資料を更新して」と伝える
3. 開発担当が資料を文字データ (.md / .txt) にして、アプリの `knowledge/` フォルダに置く
   - ファイル名がそのまま資料名になります (例: `下ノ沢自治会規約.md`、`よくある質問.md`)
   - 本文の 1 行目に `更新日: 2026-11-28` と書くと、AI は新しい資料を優先して答えます
4. 開発担当がパソコンで次を実行する
   - `node scripts/sync-chat-knowledge.mjs` … 追加・更新・削除される資料の確認 (まだ書き込まない)
   - `node scripts/sync-chat-knowledge.mjs --apply` … 実際に登録する
   - `node scripts/sync-chat-knowledge.mjs list` … 今登録されている資料の一覧
5. 最大 5 分でアプリの AI相談に反映されます

> ⚠️ `knowledge/` フォルダはパソコンの中だけに置き、GitHub には上げません (アプリのソースコードは誰でも見られる公開設定のため)。

> 💡 資料の合計が 15 万字を超えると、確認時に警告が出ます。資料が多いほど 1 回の質問の費用が上がるので、要らない資料は外すか要約してください。

### 8-C-3. 質問ログを見る (役員専用)

1. ホーム →「🤖 AI相談」を開く
2. 上部の **「🛡️ 役員: 質問ログ」** を押す (役員にだけ表示されます)
3. 右上で期間 (直近 7 日 / 30 日 / 90 日 / 1 年) を選ぶ
4. その下のボタンで **「本番の質問」「テストの質問」「すべて」** を切り替える
   - 本番のアプリで開くと「本番の質問」、テスト環境で開くと「テストの質問」が最初に選ばれています
   - テスト環境で質問したものは、一覧に黒い **「テスト」** の印が付きます

画面の見方:

| 項目 | 意味 |
| --- | --- |
| 質問数 | 期間中の質問の件数 (「会話 ○ 回分」は、ページを開いて続けて質問したまとまりの数) |
| AI が回答できた | 資料や一般知識で AI が答えられた割合 |
| 住民の評価 | 回答の下の 👍 / 👎 が押された数 |
| AI の費用 (目安) | 期間中に AI に払った金額の目安 (正確な金額は 8-C-4 の管理画面で確認) |
| 上位の AI に回した | 自動切り替えで上位の AI が答えた割合と、住民が「詳しい AI で答え直す」を押した件数。割合が高い (目安 3 割以上) なら、FAQ を書き足すか 8-C-4 の設定を見直す |
| 平均の応答時間 | 質問してから回答が出るまでの平均秒数 |
| 分類別の件数 | 「会費・お金」「ごみ・清掃・環境」など、AI が自動で分けた質問の種類。押すとその分類だけに絞り込めます |

一覧の質問を押すと、AI の回答が開きます。

> 💡 **毎週やること (15 分)**: 「AI が答えられなかった」と「👎 が付いた」で絞り込んで確認し、
> ① 多い質問は FAQ に書き足す (8-C-2)、② 個別に対応が必要そうなら要望掲示板などで役員から回答する。

> 💡 質問した人の名前は表示されません。住民には「質問内容は匿名で集計し、自治会運営の改善に使う」と案内しています。

### 8-C-3-A. テスト環境で役員だけで試す

住民に公開する前に、役員だけがテスト環境 (本番とは別の URL で動くアプリ) で AI相談を試せます。

- テスト環境は、LINE の **テスト用リンク** から開きます (開発担当が役員の LINE グループに共有します)。住民向けのリッチメニューから開くのは本番です
- テスト環境で質問した内容も質問ログに残り、**「テスト」の印付きで本番の質問と分けて** 集計されます

> ⚠️ テスト環境も、データは **本番と同じデータベース** に保存されます。テスト環境でコメント・投票・要望などを操作すると、本番の住民にも見えてしまいます。
> テスト環境では **AI相談だけ** を触るようにしてください。

> 💡 公開前にテストの質問ログを消したい時は、開発担当が Supabase の SQL Editor で次を実行します (消さずに残しておいても、本番の集計には混ざりません)。
>
> ```sql
> delete from chat_logs where environment <> 'production';
> ```

### 8-C-4. 費用と設定 (開発担当向け)

AI の費用は質問 1 回ごとにかかります (アプリの他のサービスは無料プランのまま)。
設定は Vercel の環境変数で行います。

| 変数名 | 内容 |
| --- | --- |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase の secret キー (Project Settings → API Keys)。質問ログと AI用資料の読み書きに使う |
| `CHAT_PROVIDER` | `anthropic` (Claude API、既定) または `bedrock` (Amazon Bedrock) |
| `ANTHROPIC_API_KEY` | Claude API を使う場合: Anthropic Console で発行した API キー |
| `AWS_REGION` / `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` | Bedrock を使う場合のみ |
| `CHAT_ROUTING` | `auto` (既定): まず `CHAT_FAST_MODEL` が答え、自信が無い質問だけ `CHAT_MODEL` が答え直す / `off`: 常に `CHAT_MODEL` だけで答える (以前の動き) |
| `CHAT_FAST_MODEL` | 自動切り替えで最初に答える安いモデル。既定 `claude-haiku-5-5` (1 質問 約 0.5 円) |
| `CHAT_MODEL` | 上位のモデル (`off` の時はこれだけを使う)。`claude-opus-5-5` (既定・高品質、1 質問 約 19 円) / `claude-sonnet-5-5` (約 9 円) / `claude-haiku-5-5` |
| `CHAT_EFFORT` | AI が考える深さ。`low` (既定) / `medium` / `high` |
| `CIRCULATION_TEXT_MODEL` | 回覧板の文字起こしに使うモデル。未設定なら `CHAT_MODEL` (既定 `claude-opus-5-5`、写真 1 枚 約 5〜8 円)。費用を抑えたい時は `claude-haiku-5-5` (1 枚 1 円未満、読み取り精度は要確認) |
| `CHAT_DAILY_LIMIT` | 1 人 1 日あたりの質問回数の上限 (既定 20) |
| `CHAT_GLOBAL_DAILY_LIMIT` | アプリ全体の 1 日の質問回数の上限 (既定 300)。超えると住民には「本日は受付数が上限に達しました」と表示 |

> 💡 **自動切り替えの費用の目安** (月 100〜300 件の場合): 2 割を上位の AI に回すと、上位が Opus なら 1 質問 約 4 円、Sonnet なら 約 2.4 円 (Opus だけで答える場合の約 19 円から 8〜9 割減)。
> 安い AI の回答の質が足りない場合は、`CHAT_FAST_MODEL=claude-sonnet-5-5` にするか、`CHAT_ROUTING=off` に戻してください。

> ⚠️ Claude API を使う場合は、Anthropic Console (https://console.anthropic.com) の **Limits** で **月の利用上限額** を必ず設定してください。上限に達すると AI相談は「回答の作成に失敗しました」と表示されるようになり、それ以上の請求は発生しません。

> 💡 1 質問あたりの金額は「AI用資料 + 記事が約 4〜5 万字」で、質問の 3 割ほどでキャッシュ (割引) が効く場合の目安です。毎月 Console の **Usage** で実際の金額を確認してください (5 分)。

> 💡 `ANTHROPIC_API_KEY` (Bedrock の場合は `AWS_REGION`) か `SUPABASE_SERVICE_ROLE_KEY` が未設定だと、AI相談ページは「AI相談はまだ準備中です」と表示されます。

### 8-C-5. 回覧板の文字起こしを確認・やり直す (役員専用)

回覧板は写真なので、そのままでは AI が内容を読めません。そこで、投稿されると AI が写真の文字を読み取り (文字起こし)、AI相談の資料として保存します。
AI が回覧板について変な答えをした時は、ここで **AI が読み取った内容** を確認してください。

1. ホーム →「🤖 AI相談」→ 上部の **「🛡️ 役員: 質問ログ」** を開く
2. **「📜 回覧板の文字起こし (AI が読んでいる内容) を確認する →」** を押す
3. 回覧板が新しい順に並びます。押すと AI が読み取った文字が開きます

| 印 | 意味 | やること |
| --- | --- | --- |
| 文字起こし済み | AI相談で使われている | 不要。内容が写真と違う時は「🔄 文字起こしをやり直す」 |
| 処理中 | 今読み取っている (1 件 30 秒ほど) | 少し待ってから画面を開き直す |
| 未処理 | まだ読み取っていない (この機能ができる前の回覧板や、AI の設定がない本番環境で投稿したもの) | 上の緑のボタン **「未処理・失敗の回覧板を文字起こしする」** を押す |
| 失敗 | 読み取りに失敗した (理由が赤字で出ます) | 緑のボタンか「🔄 文字起こしをやり直す」で再実行 |

> ⚠️ 緑のボタンを押したら、**終わるまで画面を閉じないでください** (1 件 30 秒ほど。件数が多いと数分かかります)。途中で閉じても、もう一度押せば続きから処理します。

> 💡 個人の電話番号・住所は、AI が文字起こしの時点で `[個人情報]` に置き換えます (市役所・団体の連絡先はそのまま残ります)。

> 💡 費用は写真 1 枚あたり約 5〜8 円で、**1 つの回覧板につき 1 回だけ** かかります (やり直すとその分また費用がかかります)。合計の目安は画面上部の「費用 (目安)」に出ます。

> ⚠️ 現在 AI の設定 (`ANTHROPIC_API_KEY`) はテスト環境にだけあります。本番のアプリで投稿した回覧板は「未処理」のままになるので、テスト環境のこの画面で緑のボタンを押して文字起こししてください (データベースは共通なので、本番で投稿した回覧板もここに出ます)。

## 11. 役員アカウントの設定方法

アプリで「役員専用機能」(現状は **各課題の名前付き回答一覧** ページ) にアクセスできるようにするには、**Supabase の `members` テーブルに `is_admin = true` を立てる** 必要があります。

### 11-1. 仕組み (簡単に)

- 住民が初めて LIFF (LINE 経由) でアプリを開くと、`members` テーブルに自動で 1 行登録されます
  - `line_user_id`: LINE のユーザー識別子
  - `display_name`: LINE のプロフィール名
  - `is_admin`: **既定で false (=一般住民)**
- 役員にしたい人を `is_admin = true` に書き換えるのは **Supabase 側で SQL を 1 回叩くだけ** です

### 11-2. 役員フラグを立てる手順

#### ① まずはその人にアプリを 1 回開いてもらう
- LIFF 経由 (LINE 公式アカウントのリッチメニュー等) でアプリを開いてもらうと、`members` テーブルに自動登録されます

#### ② Supabase で対象行を探す
1. Supabase 管理画面 → **Table Editor** → `members` テーブル
2. `display_name` 列で対象の人を探す
3. その行の `id` または `line_user_id` をメモ

#### ③ SQL Editor で is_admin を更新

```sql
-- display_name で見つけた人を役員にする例
update public.members
set is_admin = true, updated_at = now()
where display_name = '山田太郎';
-- もしくは line_user_id を直接指定する方が確実
update public.members
set is_admin = true, updated_at = now()
where line_user_id = 'U1234567890abcdef...';
```

#### ④ 役員から外したい時
```sql
update public.members
set is_admin = false, updated_at = now()
where line_user_id = 'U1234567890abcdef...';
```

### 11-3. 役員アカウントで何ができるか

- 各課題の詳細ページに **「🛡️ 役員: 回答一覧を見る」** リンクが表示される (一般住民には非表示)
- 課題の回答 (single / multiple / freetext いずれも) を **会員名付きで一覧確認** できる
- 将来追加される役員専用ページにもこのフラグでアクセス制御する想定

### 11-4. display_name を変えたい時

`members.display_name` は自動登録時に LINE のプロフィール名で入ります。
表記を統一したい (例: 「ヤマダ」→「山田太郎」など) 場合は Supabase 側で直接編集できます。

```sql
update public.members
set display_name = '山田太郎', updated_at = now()
where line_user_id = 'U1234...';
```

## 12. LINE で会員に一斉送信したい時

新しい回覧板やお知らせを、LINE 公式アカウントから **アプリ会員全員** に知らせたい時の手順です。
アプリを開くボタン付きのカードで届きます (写真付きにもできます)。

### 12-1. 頼み方
開発担当 (Claude Code を使える人) に「回覧板をアップロードしたので LINE で知らせて」のように頼んでください。

> 💡 回覧板は **1 件ずつ通知せず、まとめてアップロードした後に 1 通でまとめて知らせます**。
> 前回お知らせした後に追加された回覧板が自動で一覧になり、「新しい回覧板が ○ 件届きました」というカードで届きます (ボタンで回覧板の一覧が開きます)。
Claude Code が `line-broadcast` スキルで次の順に進めます:

1. 文面 (タイトル・本文・ボタンのリンク先) を作って見せる
2. 送らずにチェック → **宛先の人数** と **今月の残り通数** を表示
3. 依頼者の LINE にだけ **テスト送信** → 見た目とボタンの遷移先を確認
4. 依頼者が「送信 OK」と言ったら本番送信

### 12-2. 注意点
> ⚠️ **送信は取り消せません。** テスト送信で文面とリンク先を必ず確認してください。

> ⚠️ LINE 公式アカウントの無料プランは **月 200 通まで** です。**届いた人数 × 回数** で数えるので、会員 50 人なら月 4 回が上限です (テスト送信も 1 通使います)。

- 宛先は「アプリを 1 回以上開いた会員」です。公式アカウントを友だち追加していない人・ブロックしている人には届きません
- 送信履歴 (日時・タイトル・人数) は開発担当の PC の `.line-broadcast/sent.log` に残ります
